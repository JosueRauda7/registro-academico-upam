# FINDING-2026-003 — Pago ajeno accesible y serialización de usuario sensible

- Fecha: 2026-10-28. Severidad: **High**. Estado: **CLOSED**.
- Confirmación: falta de autorización y selección de campos sensibles observadas en código; respuesta HTTP no capturada.
- Ubicación: `payments.controller.ts` getPaymentById, `payments.service.ts` getPaymentById, `payment.repository.ts` findById y `entities/user.entity.ts`.
- Evidencia: [registro estático, fila 003](../evidence/2026-10-28-static-review.md).

## Observación e impacto

GET `/api/payments/:id` exige JWT, pero no rol ni propietario. El servicio no recibe actor y devuelve el pago completo. El repositorio carga student.user y la entidad User selecciona passwordHash, resetToken y resetTokenExpires sin exclusiones. El recorrido devuelve datos financieros y una relación de usuario con atributos sensibles; se debe confirmar la forma final de respuesta en ejecución.

Requiere token aceptado y conocer un UUID de pago ajeno; no se afirma que los UUID puedan enumerarse fácilmente. La lectura de datos ajenos y potencial exposición de hashes/tokens justifican High. Un reset token activo expuesto puede agravar el impacto; no se comprobó tal token en datos reales.

## Reproducción propuesta

Crear estudiantes ficticios A/B y pago de B. Con JWT de A solicitar el UUID conocido de ese pago. Se espera 403/404 sin datos; el servicio actual devuelve la entidad por ID sin comprobación. Con acceso legítimo comprobar que tampoco aparecen passwordHash/resetToken en ninguna parte de la respuesta. No se ejecutó HTTP.

## Remediación propuesta en la auditoría inicial

Pasar actor y política de acceso al servicio, restringir propietario/roles autorizados y usar DTO de salida con campos mínimos. Excluir secretos en selección/serialización como defensa adicional y revisar endpoints similares. Probar A/B, roles privilegiados permitidos/denegados, pago inexistente y ausencia recursiva de secretos. No cerrar solo añadiendo RolesGuard sin corregir minimización y acceso por objeto.

## Cierre — 2026-10-28

Corregido y verificado: [REM-2026-003](../remediation/REM-2026-003.md). Actor/propiedad y rol financiero comprobados, proyección explícita, atributos sensibles fuera de consultas y respuestas. Regresiones HTTP y PostgreSQL real sin acceso ajeno ni secretos. La descripción inicial se conserva como historial.
