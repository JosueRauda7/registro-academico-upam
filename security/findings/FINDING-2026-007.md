# FINDING-2026-007 — Lectura de otro perfil estudiantil por ID

- Fecha: 2026-11-24. Severidad: High por exposición de datos personales a otra cuenta autenticada. Estado: CLOSED tras corrección y re-test documentados. Alcance: GET /api/students/:id.
- Evidencia previa estática: StudentsController pasaba únicamente id a StudentsService.findById; JWT/RolesGuard no recibían restricción de rol en esa ruta y el servicio no comprobaba propietario. Con un ID ajeno, una cuenta autenticada podía obtener el perfil con datos personales. No se ejecutó explotación contra estudiantes reales. No es el hallazgo de pagos FINDING-2026-003: es otro endpoint.
- Contexto: al añadir aranceles al perfil se revisó su lectura para no ampliar la exposición a información financiera. La solicitud autoriza el cambio funcional y los controles asociados; no se modificaron datos personales ajenos para reproducirlo.
- Corrección: controller pasa actor y findVisibleById permite personal autorizado (administrator/administrative/collector) o student propietario por userId. Otro estudiante o teacher recibe 404. Métodos internos conservan acceso de servicio sin exponerlo directamente.
- Reproducción de re-test con fixtures: crear estudiante ficticio A y usuario estudiante B; GET con sesión de A obtiene 200, con B 404, teacher 404; tres roles de personal 200. Sin datos reales ni tokens en evidencia.
- Historial: detectado estáticamente, corregido en esta tarea y cerrado tras ensayo HTTP/DB con fixtures y verificación del control en el código. Véanse [REM-2026-007](../remediation/REM-2026-007.md) y [evidencia](../evidence/2026-11-24-student-fees.md).
- Límites: cierre específico a esta consulta; no certifica todas las rutas que puedan incluir perfiles o datos académicos.
