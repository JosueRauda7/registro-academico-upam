# REM-2026-003 — Autorización y minimización en pagos

- Fecha/responsable: 2026-10-28, Codex. Hallazgo: [FINDING-2026-003](../findings/FINDING-2026-003.md). Estado final: CLOSED.
- Causa: consulta por ID sin actor y serialización de entidad con relación User sensible.
- Solución: controller pasa actor; service limita lectura al estudiante propietario o administrator/collector y devuelve 404 al resto. payment-response.ts proyecta campos financieros y mínimos de estudiante/usuario/ciclo; las listas/creaciones de pago también usan esta proyección. User excluye passwordHash/resetToken/resetTokenExpires de selección habitual. safe-response.ts sanitiza recursivamente esos atributos como defensa adicional global.
- Archivos: payments.controller.ts, payments.service.ts, payment-response.ts, user.entity.ts, user.repository.ts, transform.interceptor.ts, safe-response.ts y pruebas.
- Re-test: dueño/administrador/colector aceptados; otro estudiante/administrativo/docente rechazados; inexistente, 404; respuestas sin secretos incluso con fixtures anidados sensibles; metadatos de selección comprobados; API con PostgreSQL real repite dueño/ajeno y minimización.
- Resultado: acceso transversal y exposición de credenciales en este recorrido corregidos. [Evidencia](../evidence/2026-10-28-remediation-tests.md).
- Límite: otros endpoints requieren auditoría de autorización propia; no se certifican por compartir interceptor. Cierre: 2026-10-28; árbol local sobre f9be37d.
