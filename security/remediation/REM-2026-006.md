# REM-2026-006 — Secretos externos y cuenta DB limitada

- Fecha/responsable: 2026-10-28, Codex. Hallazgo: [FINDING-2026-006](../findings/FINDING-2026-006.md). Estado final: CLOSED en repositorio y entorno local.
- Causa: secreto JWT y credenciales DB fijos/versionados y puertos publicados en todas las interfaces.
- Solución: Compose exige POSTGRES_PASSWORD/DATABASE_PASSWORD/JWT_SECRET externos, elimina claves Wompi de ejemplo como defaults, configura NODE_ENV production y liga los tres puertos a 127.0.0.1. La aplicación usa upam_app sin superusuario/crear bases/crear roles, con permisos DML y secuencias. Scripts de inicialización para nuevas bases y helper de rotación transaccional para base existente; .env ignorado y excluido del contexto backend. JWT_SECRET mínimo 32 bytes; valores locales generados con crypto.randomBytes e independientes.
- Archivos: docker-compose.yml, .env.example, backend/.dockerignore, auth.module.ts, database/security-role.sql, database/init-app-role.sh y scripts/secure-local-docker.cjs; README y arquitectura explican procedimientos.
- Re-test: rotación local ejecutada y servicios recreados conservando datos/volúmenes; login funcional con nueva configuración; cuenta upam_app con tres flags privilegiados false; anterior password postgres rechazado por TCP; Compose con secretos vacíos falla como corresponde; puertos solo loopback verificados; DB healthy.
- Resultado: valores conocidos eliminados como configuración operativa local; sesiones anteriores invalidadas por rotación. [Evidencia](../evidence/2026-10-28-remediation-tests.md).
- Límites: rotar también cualquier despliegue externo que haya usado los valores anteriores; no se administró producción. HTTPS, cuentas demo, backups y auditoría de dependencias requieren revisión antes de publicar. Cierre: 2026-10-28; árbol local sobre f9be37d.
