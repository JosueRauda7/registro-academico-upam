# REM-2026-002 — Separación de tokens por propósito

- Fecha/responsable: 2026-10-28, Codex. Hallazgo: [FINDING-2026-002](../findings/FINDING-2026-002.md). Estado final: CLOSED.
- Causa: guard aceptaba cualquier JWT criptográficamente válido sin distinguir su función.
- Solución: sesión con purpose access y claims sub/email/role requeridos; guard solo HS256. Recuperación exige purpose password-reset, jti aleatorio y almacena hash SHA-256; errores de token producen respuesta controlada. Credenciales ORM se seleccionan explícitamente solo para autenticación/recuperación.
- Archivos: auth.service.ts, auth.module.ts, common/guards/jwt-auth.guard.ts, repositorio/entidad User y pruebas security.test.cjs/docker-security.cjs.
- Re-test: sesión/login válido; recuperación rechazada como Bearer antes/después del uso; tokens sin propósito/claims, malformados y vencidos rechazados; recuperación rechaza sesión y reutilización secuencial. Token de recuperación rechazado también en API Docker real.
- Resultado: confusión de propósito corregida; sesiones antiguas requieren nuevo login y enlaces de recuperación antiguos deben solicitarse de nuevo. [Evidencia](../evidence/2026-10-28-remediation-tests.md).
- Límite: no se implementó revocación global de sesiones ni un nuevo subsistema de sesión; consumo concurrente del enlace requiere evaluación adicional. Cierre: 2026-10-28; árbol local sobre f9be37d.
