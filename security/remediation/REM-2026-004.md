# REM-2026-004 — Autenticidad e integridad del webhook

- Fecha/responsable: 2026-10-28, Codex. Hallazgo: [FINDING-2026-004](../findings/FINDING-2026-004.md). Estado final: CLOSED respecto de los controles corregidos.
- Causa: evento público no autenticado y asociación local usando referencia/ID arbitrarios sin cotejo completo.
- Solución: verifyWompiEvent aplica checksum SHA-256 del contrato Wompi.co sobre propiedades dinámicas, timestamp y secreto de eventos; comparación constante y exigencia de ID firmado. Gateway consulta datos completos. Service coteja ID remoto contra ID persistido al crear el pago, referencia, monto, moneda USD y método Wompi. El ID ya asociado representa la transacción creada por la cuenta configurada, sin permitir vincular otra transacción desde un evento. El repositorio usa transacción/bloqueo de fila para replay y transiciones terminales.
- Archivos: infrastructure/payment/wompi-event.ts, wompi.gateway.ts, payment-gateway.interface.ts, payments.service.ts, payments.controller.ts, payment.repository.ts y pruebas.
- Re-test: falta de configuración da 503; ausencia/falsificación de firma o ID alterado, 401; discrepancias de ID/referencia/monto/moneda, rechazo sin cambio. Evento correcto aplica una vez con mocks. Repositorio TypeORM/PostgreSQL real: dos actualizaciones concurrentes producen una sola transición, sin degradación ni ID ajeno.
- Resultado: recorrido inseguro eliminado, sin fallback sin firma. [Evidencia](../evidence/2026-10-28-remediation-tests.md). [Contrato oficial consultado](https://docs.wompi.co/en/docs/colombia/eventos/).
- Límites: sin secreto de eventos real el webhook permanece deshabilitado (503). No se probó cobro, correo ni evento comercial real; validar sandbox/cuenta/región/moneda antes de habilitarlo. Pagos previos sin ID deben conciliarse; el webhook no los vincula automáticamente. Cierre: 2026-10-28, árbol local sobre f9be37d.
