# Revisión de Swagger sobre HTTP de desarrollo

- Fecha: 2026-10-29. Agente: Codex. Alcance: resolver la documentación que el usuario no puede visualizar por la web remota; cambios previos conservados.
- Evidencia inicial: GET /api/docs y bundle daban 200, pero Helmet enviaba CSP con upgrade-insecure-requests y HSTS en un servidor HTTP. Esto ordena al navegador solicitar recursos por HTTPS aunque ese puerto no sirve TLS. La comprobación previa de solo HTTP 200 no detectaba este comportamiento del navegador.
- Cambio: backend/src/main.ts configura las dos políticas de transporte según el protocolo de FRONTEND_URL. En HTTP las omite; en HTTPS mantiene upgrade-insecure-requests y HSTS de Helmet. CSP y demás protecciones permanecen, sin permitir scripts inline ni nuevos orígenes.
- Re-test ejecutado: build NestJS correcto y contenedor backend recreado con `docker compose up -d --build backend`. DB healthy y logs de arranque correctos. Desde el servidor, por las IP LAN y Tailscale, HTML, CSS, ambos iconos, bundle, preset e init JS devolvieron 200 con tipos MIME esperados. CSP conserva script-src self, sin upgrade-insecure-requests; HSTS ausente para HTTP. /api/docs-json devuelve OpenAPI válido con 70 rutas; API privada de inscripciones devuelve 401 sin token.
- Límites: sin navegador automatizado disponible, no se verificó renderizado ni el dispositivo remoto. No se ejecutó despliegue HTTPS, pruebas de login ni suite general. La compilación verifica tipos; no hubo typecheck separado. No se modifican datos ni integraciones. No se formaliza vulnerabilidad nueva; es un defecto de disponibilidad de la documentación en el entorno HTTP.
- Pendiente de producción: configurar FRONTEND_URL HTTPS real y comprobar políticas en TLS. Este ajuste no sustituye hardening ni revisión de la exposición de Swagger pendiente en la política existente.
- Confirmación posterior: el usuario confirmó acceso a Swagger tras la corrección. Esto complementa las comprobaciones HTTP, sin sustituir pruebas automatizadas de navegador ni validación TLS.
