# Revisión de selectores y prerrequisitos múltiples

- Fecha: 2026-11-24. Base 81274f5 con cambios SSH/modales anteriores conservados. Alcance: búsquedas por label, multiselección de prerrequisitos y persistencia/coherencia de ese contrato.
- Frontend: búsqueda solo por etiquetas disponibles, en memoria y como comparación literal normalizada; no se interpreta HTML o regex del usuario ni se envía búsqueda a terceros. Valores seleccionables limitados a opciones, texto libre no escribe ID. Se mantiene respaldo select para eventos/formulario/required y combobox con teclado. Render de etiquetas como texto React.
- Backend: JWT/roles existentes administrator/administrative para mutación conservados. DTOs runtime para campos permitidos, IDs UUID, arrays únicos hasta 100; campos extra y representaciones ambiguas rechazados. Se valida existencia/carrera y actividad de requisitos nuevos, conservando inactivos ya relacionados. Sin autorreferencia ni ciclos, incluso en dos modificaciones simultáneas gracias al advisory lock PostgreSQL dentro de la transacción. Materia y relaciones se guardan atómicamente; conflictos conocidos producen respuestas controladas. No se alteró el esquema ni synchronize/seed.
- Integridad: lista ausente conserva, [] limpia; edición UI carga todos los requisitos y no pierde los adicionales. Inscripción UI requiere todos, igual que el recorrido backend existente. No se aplican cambios correctivos a relaciones históricas ajenas. Campo escalar previo compatible y depreciado, no combinable con lista; clientes antiguos que lo envíen conservan semántica de reemplazo, documentada como límite.
- Evidencia: builds y typechecks backend/frontend correctos; 6 pruebas frontend (1 búsqueda, 5 regresiones de controlador de diálogos) y 7 regresiones de seguridad backend aprobadas. `docker compose exec -T backend node < backend/test/docker-prerequisites.cjs`: {"checks":36,"result":"passed","syntheticOnly":true}. Casos: creación con dos requisitos, conservación al actualizar nombre, limpieza, escalar alternativo, duplicados/self/UUID inexistente/carrera ajena/nuevo inactivo/campos inválidos rechazados, requisito inactivo existente preservado, rollback ante código duplicado, roles no permitidos 403 y dos ediciones A->B/B->A con un éxito y un 400. Fixtures propios eliminados en finally.
- Infraestructura: ambos servicios reconstruidos/recreados con Compose; DB healthy y volúmenes preservados. Página/bundle HTTP 200 y contrato OpenAPI con el nuevo campo verificado. Sin nuevas publicaciones de imágenes o cambios de configuración de red.
- Límites: sin navegador disponible, no se certifica interacción real, eventos nativos del select, required/foco, scroll o lectores de pantalla; las pruebas de búsqueda son funciones puras. Sin pruebas sobre registros reales, pagos/correos ni despliegues remotos. Los writers SQL externos que no usen este método no quedan serializados por su advisory lock. Sin nuevos hallazgos independientes formalizados ni cierres por intuición.
